# Recovery and updates
Preserve every failed or partial attempt. Check process/thread termination, exact request/source hashes, saved first response and delivery receipt before retrying. Do not infer termination from elapsed time or an old lock.
prepare creates deterministic frozen synthetic input and request files. Repeating prepare verifies and reports the existing operation. Supply each saved first response to accept once; a different response is rejected. An existing response may be accepted without repeating inference.
finish requires all sequential responses, verifies original bytes and the complete derived export, then writes the completion receipt last. Partial export directories require reconciliation. A successful existing receipt is verified and reused, with no duplicate output effects.
Update by downloading a new tagged release into a separate empty directory, checking its manifest and running its installer. Retain the prior folder and all run artifacts. Never copy a virtual environment or overwrite local data.
Uninstall removes only the package-created environment recorded by the installer, after checking its identity and dependency inventory. Modified installations require manual reconciliation. It leaves source code, rule files and runs. To unregister the project-local specialist, close the project and remove an untouched downloaded package folder after preserving any wanted outputs. No global Codex configuration was installed.

## Native discovery prerequisites
The distribution folder must be trusted by the user and selected as the native local workspace. Do not launch the coordinator with an empty environments list for this workflow. That setting removes project roots/instructions; it is distinct from disabling specialist tools. Preserve the read-only sandbox and disabled memory settings used by acceptance tests. A missing role is a failed acceptance result. Preserve the existing response and reconcile it before any new inference.
